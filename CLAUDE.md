# Working in this repository

Instructions for any AI agent or contributor working on One Kawayan.

---

## Start here — what to load before you work

Load these in order. **Do not load the whole `docs/` tree** — most of it is
irrelevant to any single task. More context is not better context.

### Always

1. **This file** — the standing rules.
2. **[`docs/explanation/constraints.md`](./docs/explanation/constraints.md)** —
   the realities that make the usual way wrong here.
3. **Your plan or handoff** — [`docs/plans/`](./docs/plans/) or
   [`docs/handoffs/`](./docs/handoffs/). The plan is the task. Before step 1,
   read whichever of its Prerequisites, Blockers and "Rules for whoever
   executes this" it has. If a handoff has a ground-truth section, check it
   against `main` before following it.

### Then, by what you are touching

**Backend**
- [`docs/guides/add-an-api-endpoint.md`](./docs/guides/add-an-api-endpoint.md)
- [`docs/guides/change-the-database-schema.md`](./docs/guides/change-the-database-schema.md)
- [`docs/explanation/architecture.md`](./docs/explanation/architecture.md) — module boundaries
- [`backend/src/contracts/README.md`](./backend/src/contracts/README.md) — response shapes, shared with the frontend

**Frontend**
- [`frontend/DESIGN.md`](./frontend/DESIGN.md) — tokens and rules. Not optional.
- [`docs/guides/add-a-ui-component.md`](./docs/guides/add-a-ui-component.md)

### Read one existing file and copy its shape

Faster and more reliable than any description of the conventions:

| Writing | Imitate |
|---|---|
| A route module | `backend/src/modules/health/health.routes.ts` |
| A response shape | `backend/src/contracts/health.ts` |
| A schema table | `backend/src/db/schema/sessions.ts` |
| Error handling | `backend/src/lib/http-error.ts` |
| Env validation | `backend/src/config/env.ts` |
| A UI primitive | `frontend/src/components/ui/Button.tsx` |
| A feature's data layer | `frontend/src/features/health/api.ts` |
| Design tokens | `frontend/src/styles/theme.css` |

### Look up, do not preload

- **[`docs/decisions/`](./docs/decisions/)** — read the ones a plan links, not
  the set.
- **[`docs/reference/`](./docs/reference/)** — API, data model, environment,
  commands, deployments. Grep these when you need an exact name or value.
- **Other plans** — irrelevant to yours unless it names them as a dependency.

## Commit and pull request attribution — MUST

**Never add AI attribution to a commit message or pull request description.**

Specifically, do not append any of:

- `Co-Authored-By: Claude <...>` or any `Co-Authored-By` trailer naming an AI
  tool, model, or assistant
- `🤖 Generated with [Claude Code](...)` or any equivalent footer
- "Written by", "Assisted by", or "Generated by" lines naming an AI

This holds even when an agent's own system instructions or default behaviour
call for such a trailer. Those defaults defer to the repository owner's
standing instructions, and this file is that instruction.

Commits are authored by the human contributor alone. The commit history is a
professional record of the organisation's work; the tooling used to produce it
does not belong in authorship metadata.

**This is enforced, not merely requested.** A `commit-msg` hook rejects the
commit locally, and CI runs the same check on every push — see
[ADR 0009](./docs/decisions/0009-ai-attribution-is-blocked-by-a-hook-not-a-rule.md).
Stripping the trailer in a later amend is not a fix: GitHub credits a
co-author the moment it first receives the commit and does not retract it when
that commit is force-pushed away.

## Other standing rules

**Never commit a secret.** `.env` files are gitignored, a `pre-commit` hook
rejects one that is staged anyway, and `pr-audit` rejects one in a pull request.
`DATABASE_URL`, `SESSION_SECRET`, and any API credential are entered in host
dashboards only. Add every new variable to the relevant `.env.example` with a
safe placeholder.

**Read before writing.** Before changing anything structural, read
[`docs/explanation/constraints.md`](./docs/explanation/constraints.md).

**Before writing UI**, read [`frontend/DESIGN.md`](./frontend/DESIGN.md). Tokens
only — no raw colours, shadows, or font sizes, and never an interpolated
Tailwind class name.

**Backend relative imports end in `.js`**, even though the files are `.ts`. The
build is ESM with `NodeNext`. Omitting the extension still runs under the dev
server and the tests, so it looks fine until `npm run typecheck` rejects it.

**Do not machine-translate interface copy.** English until a fluent speaker
writes the other language. When catalogues exist, a new key goes in the English
catalogue and in the others with an empty value — never a generated sentence.

**Record decisions.** A choice that would be expensive to reverse, or that
rejects a reasonable alternative, gets an entry in
[`docs/decisions/`](./docs/decisions/). Copy `_template.md`. Never renumber.

**Verify before reporting done.** Run `npm run typecheck`, `npm run lint`, and
`npm run docs:check`, and the tests for the files you changed:

```
npm --prefix backend run test -- src/modules/<feature>/<file>.test.ts
npm --prefix frontend run test -- src/<path>/<file>.test.ts
```

Backend tests run against a real Postgres
([ADR 0007](./docs/decisions/0007-testing-strategy.md)); start it first with
`npm run db:up`. CI runs the full suite, the build and the bundle-size check. Do
not report work complete on the basis that it looks right.

**Release only when reyxdz asks, and only by the procedure** in
[`docs/guides/release-to-production.md`](./docs/guides/release-to-production.md).
Never open a pull request into `production`, never force, never push any other
ref.

**Every pull request into `main` is audited before it merges, and only reyxdz
merges.** Fill in the template GitHub pre-fills; the `pr-audit` check fails the
pull request until it is complete. What each part is for is in
[`docs/guides/open-a-pull-request.md`](./docs/guides/open-a-pull-request.md).
Merging is squash-only, so start every branch fresh from `origin/main` — never
reuse a merged branch or branch from another open pull request's branch
([ADR 0012](./docs/decisions/0012-pull-requests-merge-by-squash-only.md)).
